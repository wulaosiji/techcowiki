# Full-project technical review and optimization notes

Review date: 2026-09-13. Baseline was `3268212` on `origin/cursor/geo-first-encyclopedia-e3a9`; remote `main` then had only the initial README. Fixes were kept on the local `codex/project-review` branch.

Scope covered project config and dependencies, data generation and refresh, autolink and citation rendering, bilingual pages and search, mobile layout, JSON-LD / JSON API / Markdown / RSS / sitemap, Cloudflare Pages routing, and CI plus acceptance scripts.

## Issues fixed

| Priority | Problem and impact | Fix |
| --- | --- | --- |
| P1 | Dependency audit reported 5 vulnerabilities on the Astro, sharp, esbuild, and Vitest chain | Pin Astro at 7.3.2, upgrade Vitest to 4.1.11, refresh the lockfile; audit result is 0. A static deploy does not mean every reported server-side issue is reachable, but the upgrade also protects the develop and build path. |
| P1 | JSON-LD was inserted with raw `JSON.stringify()`, so content containing `</script>` could break out of the script element | Escape `<` in one place via `scriptJson()`; add tests for a hostile closing tag and a data round-trip. |
| P1 | E2E returned success when the browser binary was missing; hosted checks accepted a 200 error page | Missing Chrome fails explicitly; every healthy page must be 200 and every missing page must be 404; add response-type, JSON-body, and HEAD checks. |
| P1 | Structured data described the current headquarters as the founding place and every historical company link as a current job | Headquarters uses `location`; people use role-bearing `affiliation`; the graph uses `associated-with` and keeps the existing role text. |
| P1 | A failed source fetch was treated as “record missing” and could write a partial cache file; a null Wikidata payload also threw on dereference | Requests use a timeout, limited retries, and explicit failure; true 404s are handled separately; the cache is replaced atomically after success. Tests cover network failure, rate limits, server errors, auth errors, and invalid JSON. |
| P2 | `astro check` had 8 errors and CI did not run typecheck | Add Node types, fix optional-field access, drop unused imports; CI runs the full check. |
| P2 | Search did not trim whitespace, sector/region used substring match, and unknown params disagreed with the form | Normalize whitespace, case, and full-width characters; support space-separated keywords; filters use complete slugs; unknown values behave as unset. |
| P2 | Search HTML was about 3.09 MB, with a lot of repeated haystack text and Markdown URLs | Build a de-duplicated search-term index; keep all 200 entity cards and searchable Chinese, aliases, products, and FAQ text. |
| P2 | Autolink rebuilt the dictionary and regex for every paragraph and lowercased every token; canonical URLs inside existing Markdown links could be rewritten again | Reuse the bilingual dictionary and regex per entity; lowercase only when the body changes; leave existing links and inline code alone. |
| P2 | After JSON dropped citation marks, callers could not see which sources backed a paragraph, answer, or fact | Add bilingual `citations` and per-field `sourceIds`; OpenAPI describes the citation shape; every ID is checked as resolvable. |
| P2 | Pages 404 fallback requested an `index.html` path that clean-URL redirects could disturb; HEAD was replayed as GET | Request `/zh/404/` instead; keep GET/HEAD semantics, 404 status, and no-store; set noindex. |
| P2 | Every page inlined the same CSS and every link was prefetched, including large machine assets | Extract shared CSS; enable hover prefetch only on entity cards. |
| P2 | Filter controls lacked accessible names, very narrow viewports could overflow, and search had no result count | Add control names and a result status; allow long text to wrap; cap input and grid width; check 320px pages. |
| P2 | RSS treated the stable ID as a permalink by default; dataset metadata omitted the regions Markdown entry | Mark GUID `isPermaLink="false"`; add `regionsMarkdown`. |
| P2 | Astro 7 can start a background preview under an agent; the old child-process cleanup did not always stop the real server | E2E uses Astro’s programmatic preview API and stops it in `finally`; Pages child processes are cleaned up as a process group. |

## Compatibility notes

- Local and CI require **Node.js 22.12+**; `.nvmrc` is 22. The framework jump is Astro 5 → 7. `compressHTML: true` whitespace behavior is kept explicitly and was rechecked on every static page and interaction.
- API documentation version in this review was **1.3.0**. Entity URLs and `/api/v1/` paths kept their shape. Graph edges changed from **`works-at` to `associated-with`**; existing graph consumers must update that type check. The new `role` field is the existing role text and does not infer employment dates.
- `citations.definition`, `citations.lead`, and section / FAQ / claim `sourceIds` were `{ en: string[], zh: string[] }` at review time. Those IDs point at the same entity `sources` array.
- Search matches every keyword together and can combine fields; unknown sector/region params behave like the empty option.

## Verification scope and release status

This pass completed a technical and data-structure review, a fact-consistency check of existing entries, and browser acceptance on representative pages. It did not re-verify every commercial fact against every external source, and it did not bump entry review dates. Freshness and source accuracy still need the editorial process.

Browser functional checks blocked third-party font requests so the network would not affect assertions. Real font load and CDN Web Vitals were not measured. External source URLs were not crawled for worldwide reachability.

This pass did not deploy or change DNS; Pages was accepted on the local runtime. A live release still needs `HARNESS_BASE=https://techcowiki.pages.dev npm run harness:host` after deploy. The GitHub CI workflow was updated; its remote result has to be confirmed after push.
